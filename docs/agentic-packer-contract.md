# Deterministic evidence packing contract

`electron/services/workflow/evidence-packer.ts` is the workflow boundary between an ordered `SelectionPlan` and final generation messages. It accepts only evidence IDs, resolves those IDs through the supplied `WorkflowEvidenceStore` for the exact `RunSpec.snapshotId`, and builds source entries from the resolved records. It never accepts caller-provided source text, paths, summaries, or declaration bodies.

## Selection and source integrity

- Repeated selected IDs are deduplicated while preserving first occurrence. Unknown IDs, stale snapshots, invalid paths/ranges, wrong snapshot IDs, and content whose SHA-256 does not match its evidence record are rejected.
- A required bundle must refer only to selected IDs. Every selected member in any required bundle is packed as one mandatory set. If that set cannot fit, `packEvidence` returns `status: 'conflict'` with `reason: 'required-bundle-too-large'` and all mandatory members in `omittedIds`; no member is clipped or silently removed.
- Other selected evidence is attempted in selection priority order. An item that does not fit is recorded with omission reason `budget`, and lower priority items are still considered. The resulting output is a complete source serialization or a structured conflict; source text is never clipped.
- Intersecting ranges from the same file are merged only when every shared line agrees. Each fit trial merges only the records currently being considered, so an adjacent optional range cannot become mandatory by merging with a required range. Their evidence IDs remain in `sources[].ids`. Missing lines between separate ranges are represented as explicit `omission-gap` data. Identical text from different files remains separate.
- Each source entry contains `ids`, `fileId`, `relPath`, `displayRange`, nullable `originalRange`, SHA-256 `hash`, and `sourceKind`. A null original range means the source adapter could not establish original line mapping. Document excerpts are emitted only as their resolved spans. Declarations are preserved only when present in resolved records; the packer does not infer missing bodies.
- Source records are serialized as JSON data beneath a fixed untrusted-evidence preamble. There is no model-written summary in this format.

## Budget measurement and immutability

The final result is made by calling the trusted `buildMessages(contextText)` adapter. The callback must be deterministic and side-effect free. At fit time, at least one user message must contain the complete `contextText` verbatim; a builder that ignores, crops, or escapes that text is rejected. Dispatch repeats this check against the actual frozen logical messages, so the manifest cannot claim evidence absent from the request. Its complete messages, including system text and prompt/schema preamble, are cloned and frozen. `contextChars` sums every message content length; `serializedChars` measures `JSON.stringify(messages).length`; `estimatedInputTokens` is `estimateMessageTokens(messages)` plus `ceil(max(0, serialized UTF-8 bytes minus raw content UTF-8 bytes) / 4)`. This counts JSON framing and role/field structure without charging the source text twice. It is an explicit conservative local estimate, not provider token usage.

`maxChars` defaults to the selected granularity's `CONTEXT_CHAR_BUDGETS` entry and may not exceed it. Both total message content and serialized message length must fit. `maxInputTokens` defaults to the lower of `spec.generationInputTokens` and the model context window less `spec.generationOutputTokens`; explicit values must be finite positive integers no greater than either ceiling. IDs, bundles, unresolved references, resolved record count, and total resolved source bytes are bounded before packing. A fit decision always measures the complete candidate messages; Unicode is serialized without source clipping. If no selected source fits, the result is a `no-evidence` conflict instead of a packed context with zero evidence IDs.

`PackedManifest` is version 1 and includes run, project and snapshot IDs; the full deduplicated `selectedIds`; the mandatory `requiredIds`; ordered `packedIds`; explicit `{id, reason}` omissions; source entries; SHA-256 `requestHash` over canonical final messages; SHA-256 `manifestHash` over the complete manifest payload excluding that hash; estimated token count, serialization overhead, serialized/content character counts, and effective limits. The manifest and all nested arrays/objects are immutable.

## Dispatch binding

Pass `makeDispatchGuard(context)` as `ModelCompletionInput.dispatchGuard`. `createModelGateway` invokes this guard against its frozen logical messages in `beforeRequest`, before the transport can issue fetch and before the ledger marks a request dispatched. The guard recomputes the request hash, serialized length and token estimate, validates the manifest hash and stored limits, and rejects any changed, appended, cropped, or over-budget message list with a static `WorkflowError('invalid-argument')`. `assertPackedDispatch` is also available for direct assertions. Keep protocol serialization transformations inside the transport; the guard binds the exact logical messages that the gateway will hand to it.

`deterministicSelectionFromEvidence(ids)` is a small adapter for static selection policy. It creates an ordered `SelectionPlan` with no required bundles and does not change or replace the legacy context builder.
