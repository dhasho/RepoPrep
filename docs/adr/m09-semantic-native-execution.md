# M09 native execution and parent observation (E3b)

Date: 2026-11-11. This composes the accepted E3a encrypted snapshot with the E1 semantic execution and E2 frozen validator. It implements a controlled measurement entry. It does not register the M09 checker, supply blind judgments, read private grading keys, or establish a quality pass.

`run-semantic-profile.cjs` is the Node parent. It inspects the exact clean checkout, loads only `projects.json`, `review-packet.json` and `repair-samples.json`, creates one opaque plan/map, fixes the reference and unchanged budget contract, and creates a private DACL-secured temporary runtime. It bundles the entry from that checkout with esbuild, externalizing Electron, and records the entry source bytes and complete bundle hashes. The bundle uses the original contract module URL for its unused default dataset location; every executed dataset read receives the exact frozen explicit directory. A second clean source check precedes the one hidden direct Electron spawn. The environment is an allowlist, both pipes are bounded, and no prepare/decrypt child precedes execution.

The native entry calls `bootstrapNativeSemanticContext` synchronously before its first await. That issuer requires Windows Electron's browser/main process, the main thread, pre-ready app state and absence of `ELECTRON_RUN_AS_NODE`. It checks the parent PID, owned root/entry identities, bundle hash, allowed source/output/claim paths and non-overlap. It calls the unchanged E3a capture once and stage once, applies the four returned distinct paths unchanged, then releases the capture. The E3a helper remains the only encrypted staging implementation. The native token is held in a private WeakMap; JSON values, copies and synthetic claims cannot act as tokens.

After ready, the context invokes the directly imported production `getPrivateProfile(selectedProfile.profileId)` once. Raw saved metadata must match the E3a capture, including the domain-separated fingerprint of the exact saved base URL. Optional field absence is preserved by both E3a and the store; defaults are applied only by the shared semantic configuration derivation. The private profile and derived configuration are frozen. Every E1 current-profile callback returns the same in-memory object; it never rereads or decrypts settings. Configuration is checked against the key and raw endpoint before it is put on the control pipe. Public errors are finite codes. Unknown exception text, raw endpoints, keys, prompts and model responses are never forwarded to stdout or stderr.

The same live child publishes one bounded ready message containing the two nonce bindings and derived nonsecret configuration. The parent validates the ready/source/public/plan/map/bundle bindings and constructs the exact existing real `createSemanticAuthorizationDraft`. It writes the grant with exclusive creation, fsync and identity-bound readback, then sends one matching canonical grant message and closes stdin. The child requires exactly one canonical bounded JSON line **and EOF**. Duplicate, malformed, extra or unterminated input cannot authorize a request. It independently reconstructs the full authorization, including the original budgets, checks the control artifact's exact bytes and nonce/hash bindings, and then permits one claim/start.

Ordinary exported `claimSemanticExecution(real)` refuses after clean source inspection and before caller profile access or claim writes. Ordinary `executeSemanticEvaluation(real)` also remains closed. Only the native token path invokes the private shared core. It supplies the captured profile internally and directly imported production `chatCompletionStream`; there is no caller transport, custom fetch, currentProfile or dependency override for real execution. The child bundle contains one native registry instance shared by its CJS entry and bundled ESM runner. The parent validator dynamically imports the canonical source CJS launcher only when given a parent proof, so it uses the same parent registry that observed the child and does not accidentally bundle another proof registry into the child.

All 100 E1 denominator slots, the genuine S/R/V services, original run specs, ledger, admission accounting and synchronous final-fetch fence remain in use. The unchanged limits are 80 review/20 repair, at most 240 requests, 1,600,000 admitted input tokens and 1,146,880 output reservations. Per-case review limits are 2/12,000/8,192 and repair limits 4/32,000/24,576; call output caps remain 4,096/8,192. Original coarse/fine requests 5/14, input/output 128,000/65,536 and wall-clock 600,000ms stay unchanged. Unknown and unknown-unsent retain conservative holds and seal later cases. A production final-fence failure after admission can remain `unknown` even when loopback proves zero wire requests; this does not refund its admission or reservation. The launcher never retries a paid run.

`native-provenance.json` commits source/public/plan/map/config/authorization/grant/claim relationships, the parent/child nonces, bundle/source hashes, native versions, fixed production transport identity and exact bootstrap/read counts. It contains no local paths. The execution freeze commits that artifact's exact bytes together with all existing E1 artifacts. To avoid a self-referential hash, the separate owned outcome binds both the final exact freeze hash and provenance hash. The parent must observe that exact outcome on the direct child pipe, match its owned outcome file, and wait for the actual direct close before capturing expected freeze bytes or issuing a private in-memory parent proof.

The independent validator still checks every public byte, authorization/start/claim, original spec/fingerprint, manifest, source-read receipt, reservation, aggregate and journal chain. It additionally checks native provenance and the parent proof's exact freeze/output identity. Arbitrary anchors, relabeled synthetic archives, missing native evidence and nonce/source/config/grant changes cannot satisfy `requireReal`. Detached structural validation can report `nativeProvenance: unavailable` and cannot return complete real execution. Provenance JSON alone never establishes that an external call occurred.

A successful `launch(options)` returns the validated execution, `nativeParentProof`, a defensive copy of `expectedFreezeBytes`, output location and cleanup result. **The proof is process-local and belongs to that same long-lived Node host and canonical CJS module instance.** A later trusted E2 adapter can close over those values and invoke `validateFrozenSemanticExecution` with `requireReal`, the exact freeze bytes and that proof. A detached CLI process cannot recreate them from disk. The future formal `npm run verify:agentic:m09` real path must execute under that same host authority, or a separately reviewed bounded control channel; this patch does not add a replay issuer or claim that the CLI completes the formal M09 gate. The current CLI reports execution completeness and `awaiting-independent-blind-judgments`; an incomplete execution exits nonzero. Quality remains `not-evaluated`.

The parent waits for close on success, process errors, bounded-pipe violations, interrupt signals and the overall timeout. It closes stdin and kills only the owned child. Outputs, persistent claims, failed/partial runtimes and unexpected entries are preserved. Successful runtime cleanup requires the private runtime token, captured absolute boundary, directory/file identities, known control-file hashes and allowed bootstrap paths. Its conservative stage inventory permits only the two E3a staged encrypted files and the four initially empty runtime directories; additional Chromium files, replacements or other unexpected entries preserve the entire runtime for diagnosis. It refuses links/reparse points, hardlinks and replacement roots, then removes individual captured entries after direct close. It never recursively deletes an unchecked target and never includes output, claims or source settings among cleanup targets.

Implementation validation uses synthetic public profiles and the actual production HTTP transport over loopback. It covers awaited admission, a zero-wire synchronous final fence, genuine SSE usage, retained unknown holds, all100 cases, rejected native/copy/caller paths, exact single-message EOF handshake, ready/grant binding changes, relabel/anchor tampering, direct-close/error/timeout ordering, cleanup and bundle registry uniqueness. No Electron/native composition, saved profile/config read, provider call, accepted E3a R2 repeat or M08 run is performed during this stage. A root-approved native synthetic composition and a separately chosen concrete real measurement remain future steps after review.
