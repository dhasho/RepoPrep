# Genuine new-run W/L journal and read-only prefix classification

Date: 2026-11-11. Status: narrow storage/accounting component (A2a). The production runner, coordinator, UI and existing W/L/A0/A1 implementations are unchanged.

`createWorkflowLedgerJournal({storageDirectory, spec, limits?, onDurableStep?})` synchronously prepares the complete canonical original with A0/A1 before any asynchronous work, creates a genuine durable BudgetLedger, and opens its own production WorkflowStore. Its options reject additional fields, proxies and accessors; callers cannot supply a store, attempt, binding, validator, genesis, epoch, acknowledgement or recovery authority. The optional quotas only tighten W's ceilings. The optional durable-step callback is W's existing main-program instrumentation/fault seam and cannot return an acknowledgement or replace W.

Under that exclusive acquired owner, only a genuinely absent logical run may start. Existing, empty-attempt, unavailable, torn and terminal sources are rejected. The factory begins a real attempt, persists a created envelope with the full empty original ledger state, validates the real W acknowledgement, and accepts the causal A1 step before returning a frozen session. Initialization errors revoke and close owned resources without deleting evidence or retrying. The embedded canonical original remains JSON text so a legal temperature -0 survives W's outer serialization.

The session exposes the frozen original spec, genuine ledger, DurableModelJournal, synchronous finish(), and asynchronous close(). Its journal uses the actual W owner as fence and actual attempt UUID. Synchronous assertCurrent checks the genuine W attempt and exact run/project/snapshot/attempt/fence context; it provides no asynchronous project authorization. finish() only revokes issuance and blocks the live ledger; it writes no terminal record. close() revokes immediately and awaits the real W close, pending work and listener shutdown.

A private queue includes each model append, acknowledgement checks and A1 cursor acceptance. Inside W's synchronous builder, the actual binding, full epoch, next sequence and complete previous reference must equal the accepted cursor. The builder derives the logical position from that context, invokes the original L state builder once, validates the full envelope and prepares its causal step before returning. The real acknowledgement must match schema, sequence, complete payload, reference epoch/ID, and SHA256/length of W's exact entire outer record. Only then does A1 accept the step and the promise resolve with precisely the proposed logical position. W still applies its whole-record quotas before transport admission.

Any append, builder, state or acknowledgement failure permanently revokes the session and blocks the live ledger. This includes a flushed immutable file followed by a lost acknowledgement. Accepted cursor state is never reused for continuation after such a failure; no rollback, builder retry or automatic reopen is attempted. Full surviving physical prefixes remain independently readable. The queue covers model events after created only. It does not serialize read/tool/control settlement or L's afterFlush work, and exposes no API that claims those contracts.

`classifyWorkflowLedger({storageDirectory, spec})` internally performs a fresh production readWorkflowStore with the real A1 critical validator and the original-spec ledger validator. The ledger component schema is workflow-ledger-state-v1. Unknown component schemas fail closed through W. The result distinguishes absent, unavailable, initialized-without-created, verified-nonterminal, terminal and manifest-mismatch. Invalid caller options/original spec are rejected before reading. W verification is followed by exact checks of original JSON/binding, schema, sequence/reference ID, actual reference epoch versus payload epoch, complete previous references and the real latest tail. A1 receives fresh exact {payload,reference} projections, never an injected verified view.

A selected manifest must anchor an actual record, contain exactly one correctly typed ledger component equal to A1's full state at that anchor, and have terminal stage consistent with the anchor's seal outcome. Its older anchor remains diagnostic; classification returns the newest journal state. Unavailable latest evidence has no fallback. Sealed accounting is returned unchanged, including unresolved reserved/dispatched rows; it never goes through L restore conversion. Returned states/references are immutable integrity data and grant no recovery authority, restored ledger, source capability, paid permission or continuing session. B0 exclusion/terminal integration and recovery continuation remain separate future work.

Validation uses actual Windows W ownership and immutable files, production gateway and L, synthetic profiles/transports, and a global fetch trap. Focused tests cover flush ordering, whole-file byte/hash checks, concurrent causal appends and exactly-once state builders, conservative unknown holds, quota and acknowledgement-loss poisoning, initialization failures, synchronous finish/close fencing, torn/latest and outer/payload mismatch rejection, older manifests with newer tails, manifest mismatch and unchanged sealed accounting. Node typecheck and diff-check accompany the focused tests. No provider requests, unrelated native credential tests or broad M08/E3a suites are part of this change.
