The actual accounting checks formerly in ledger-critical-transitions.ts now live once in critical-accounting-internal.ts. Both folds call this implementation after their own closed structural validation. It preserves V1 time, capacity, issued-ID, model reservation/intent/receipt/unknown, read/tool, diagnostic, epoch and recovery behavior and V1 errors. V2 currently admits only created, investigation model/read/tool accounting, recovery, cancelled/failed seal and one plan. Created has null plan lineage. All later accounting/recovery/seal events preserve it exactly. Repeated or changed plans, generation/review/repair/compensation stages and completed/succeeded terminals are rejected. Healthy accounting is an integrity precondition; it cannot prove an actual completed business investigation.

original-plan-metadata.ts exports ORIGINAL_PLAN_VERSION_TAGS, ORIGINAL_PLAN_VERSION_COMMITMENTS and ORIGINAL_PLAN_RETRY_POLICY. This data module imports no generation runtime. Plan data stores original binding, complete RunSpec/config and objective/snapshot/evidence/investigation/context commitments, the fixed version commitments, writer variant, original question budget, captured remaining request count, planned sum and ordered bounded slot descriptors. Ordinals distinguish equal-content groups. Slot kinds, finite weights, quotas and source-group hashes contain no labels, paths, prompts, reply text, credentials or grading content. Planned total equals the actual quota sum; infeasible planner boundary totals are representable. Validation owns and freezes the data and rejects getters, proxies, sparse arrays, extra fields and malformed commitments.

Cumulative lineage is bounded to 4 MiB and every logical position commits it. The 64 MiB critical record cap remains unchanged. Tests measure the complete W-shaped outer bytes, including repeated lineage, but do not allocate W run/aggregate capacity. Real W acknowledgement, anchored tail/readback, same-queue commit, run/aggregate admission and before-expense capacity checks belong to the subsequent genuine host slice. Caller-shaped references remain untrusted data, and a self-consistent truncated prefix cannot be detected without a trusted latest anchor.

No codec, metadata, fold token or readback descriptor grants project/source/model/storage/recovery capabilities. The future private owner must derive the genuine plan once from the actual completed investigation, existing shared grouping/quota rules, evidence and captured snapshot; it must use these constants, keep display/evidence capabilities private, select V2 before any original expense and verify real W acknowledgement/readback before accepting the plan. A spent V1 owner cannot upgrade or restart. This slice adds no host wiring, generation, IPC/UI/default changes or provider calls.
