## Owner and attempt capabilities

Mint a private WeakMap owner capability only after successful listen. Keep the listener private. A program-issued attempt capability joins owner/store identity, logical run/project/snapshot, a new attempt UUID and monotone fencing epoch. JSON, copied objects and matching metadata never recreate authority. Serialize allocation, attempt transitions, journal callbacks and manifest publication through one owner queue. Recheck capability/root/fence/signal after every await and immediately before publication.

Cancellation/terminal invalidates the attempt synchronously. Explicit close invalidates all capabilities before closing the OS handle; handle error/close does so synchronously when delivered. Drain/reject pending writes before intentional release. A queued or late old callback cannot publish or release a newer attempt/project slot. A terminal physical attempt remains terminal. Resume may issue a new physical attempt for the original logical run; it never relabels old producer/request identities or creates a fresh budget.

## Epochs, components and commit manifests

Do not use a global mutable HEAD as storage authority. Allocate monotone owner/attempt epochs via exclusive non-overwriting filesystem names; flush the marker before admitting mutations. Every component, transition and manifest carries its producing epoch and run identity. Readers observe the newest issued epoch and its validated carry-forward chain. Old-epoch late writes cannot replace a newer epoch. A torn newest marker/commit is explicit unavailable or verified-prefix recovery, never a successful old checkpoint with a reset budget. Bound marker counts and scans; exhaustion fails closed.

Write strict bounded immutable components using program-owned names, flush them, and publish a versioned immutable commit manifest only after all referenced components exist with exact schema, identity, byte length and sha256. Include parent manifest/hash, complete original run/config/schema/policy binding, attempt/fence, stage/sequence and trusted critical-journal position. Perform the final check and publication within the owner queue. A HEAD may be a cache hint only. Validate the entire committed set on read; uncommitted temp files are not a completed checkpoint. Preserve the prior valid committed prefix on failure. Never overwrite components belonging to another epoch/commit. Empty/malformed/hash-mismatched/missing components do not yield partial usable state.

Module W exposes typed, bounded component/manifest storage with mandatory caller-supplied schema validators for each known component kind. It does not interpret arbitrary JSON as a ledger, evidence store or source capability. Later integration must validate the full ledger and every newer critical record before recovering budget authority. A store manifest alone cannot erase charges or authorize paid dispatch. Raw prompt/source/hidden reasoning/credentials are outside default capture; optional recorded-visible-response components require an explicit separate program-owned payload policy. Generated user result/checkpoint content remains distinct from raw source/model response capture.

## Capacity

Trace retention remains20 runs/7 days/100MiB for metadata only and is not implemented by this module. Use an independent workflow-store ceiling of1GiB aggregate and256MiB per logical run. Component maxima: ledger64MiB, critical journal64MiB, optional replay/request payload32MiB, result8MiB, question/review/revision sidecar4MiB each, snapshot metadata8MiB; manifest and control records are separately bounded at1MiB. Actual pending/temp/marker/component/journal bytes count before admission; immutable shared bytes count once. All arithmetic is safe-integer checked. Caller may tighten, never raise these maxima. Reserve the full worst-case pending transaction capacity before writing; on exhaustion publish nothing, keep existing committed data and stop new durable work. There is no automatic eviction of active attempts, unresolved failures/unknown billing gaps, user-pinned content or latest valid prefixes. Garbage collection is outside W until reference/lease protection has tests. These are storage limits, not new model/read/time allowances.

The future ledger adapter must reconcile encoded record bounds, reservation/intent/receipt projections and possible missing-output state with this quota before HTTP. Module W alone must not claim durable model admission is safe or that all possible64MiB ledger states leave capacity for another request.
