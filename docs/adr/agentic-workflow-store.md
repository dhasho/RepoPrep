Date:2026-11-10. Status: root contract accepted for the isolated store/owner module. This does not assert M10/M11 completion, change a product default or authorize a provider experiment.

## Boundaries and native evidence

Add main-process-only services in a new isolated workflow-store/v1 namespace. Legacy draft v1/checkpoint v2/result files remain unchanged. No renderer, page, style, asset, public IPC, preload, saved-setting, dependency or package-version change belongs to this module.

Choose a private Windows named-pipe listener keyed by sha256(protocol namespace + reliable nonzero bigint physical root dev/ino). Resolve and validate the root, keep bigint identity as decimal strings, reject unstable/unavailable identity, never fall back to another endpoint on collision. Destroy every client socket without application bytes. Use the actual OS listener, not a PID/timeout/heartbeat/stale-lock file. Do not steal an owner. Unsupported platforms are explicitly unavailable for this experimental durable service, preserving the legacy path; Linux/macOS support needs separate native proof and must not unlink stale pathname sockets. UNC/mapped/cloud/other-filesystem equivalence and a malicious local process bypassing the protocol are not established by the NTFS probe. Do not advertise those as proved guarantees.

Root identity and all component path boundaries must be revalidated before critical effects and after awaits. Reject symlink/reparse descendants and unexpected directory replacement; no caller/model-controlled arbitrary destination. Hash integrity is not authentication against a local user who can rewrite every file. Do not claim Node pathname checks remove all adversarial filesystem check/use races.

## Owner and attempt capabilities

Mint a private WeakMap owner capability only after successful listen. Keep the listener private. A program-issued attempt capability joins owner/store identity, logical run/project/snapshot, a new attempt UUID and monotone fencing epoch. JSON, copied objects and matching metadata never recreate authority. Serialize allocation, attempt transitions, journal callbacks and manifest publication through one owner queue. Recheck capability/root/fence/signal after every await and immediately before publication.

Cancellation/terminal invalidates the attempt synchronously. Explicit close invalidates all capabilities before closing the OS handle; handle error/close does so synchronously when delivered. Drain/reject pending writes before intentional release. A queued or late old callback cannot publish or release a newer attempt/project slot. A terminal physical attempt remains terminal. Resume may issue a new physical attempt for the original logical run; it never relabels old producer/request identities or creates a fresh budget.

## Epochs, components and commit manifests

Do not use a global mutable HEAD as storage authority. Allocate monotone owner/attempt epochs via exclusive non-overwriting filesystem names; flush the marker before admitting mutations. Every component, transition and manifest carries its producing epoch and run identity. Readers observe the newest issued epoch and its validated carry-forward chain. Old-epoch late writes cannot replace a newer epoch. A torn newest marker/commit is explicit unavailable or verified-prefix recovery, never a successful old checkpoint with a reset budget. Bound marker counts and scans; exhaustion fails closed.

Write strict bounded immutable components using program-owned names, flush them, and publish a versioned immutable commit manifest only after all referenced components exist with exact schema, identity, byte length and sha256. Include parent manifest/hash, complete original run/config/schema/policy binding, attempt/fence, stage/sequence and trusted critical-journal position. Perform the final check and publication within the owner queue. A HEAD may be a cache hint only. Validate the entire committed set on read; uncommitted temp files are not a completed checkpoint. Preserve the prior valid committed prefix on failure. Never overwrite components belonging to another epoch/commit. Empty/malformed/hash-mismatched/missing components do not yield partial usable state.

Module W exposes typed, bounded component/manifest storage with mandatory caller-supplied schema validators for each known component kind. It does not interpret arbitrary JSON as a ledger, evidence store or source capability. Later integration must validate the full ledger and every newer critical record before recovering budget authority. A store manifest alone cannot erase charges or authorize paid dispatch. Raw prompt/source/hidden reasoning/credentials are outside default capture; optional recorded-visible-response components require an explicit separate program-owned payload policy. Generated user result/checkpoint content remains distinct from raw source/model response capture.

## Capacity

Trace retention remains20 runs/7 days/100MiB for metadata only and is not implemented by this module. Use an independent workflow-store ceiling of1GiB aggregate and256MiB per logical run. Component maxima: ledger64MiB, critical journal64MiB, optional replay/request payload32MiB, result8MiB, question/review/revision sidecar4MiB each, snapshot metadata8MiB; manifest and control records are separately bounded at1MiB. Actual pending/temp/marker/component/journal bytes count before admission; immutable shared bytes count once. All arithmetic is safe-integer checked. Caller may tighten, never raise these maxima. Reserve the full worst-case pending transaction capacity before writing; on exhaustion publish nothing, keep existing committed data and stop new durable work. There is no automatic eviction of active attempts, unresolved failures/unknown billing gaps, user-pinned content or latest valid prefixes. Garbage collection is outside W until reference/lease protection has tests. These are storage limits, not new model/read/time allowances.

The future ledger adapter must reconcile encoded record bounds, reservation/intent/receipt projections and possible missing-output state with this quota before HTTP. Module W alone must not claim durable model admission is safe or that all possible64MiB ledger states leave capacity for another request.

## Actual Module W API and adapter boundary

The isolated implementation exports `openWorkflowStore(options): Promise<WorkflowStore>`, `readWorkflowStore(options, binding): WorkflowStoreRead`, `createWorkflowVisiblePayloadPolicy(validateVisiblePayload)` and the fixed kind/limit constants. No app entry point invokes these services yet.

`WorkflowStoreOptions` requires an existing program-owned `storageDirectory` and `validators: Partial<Record<WorkflowComponentKind, { schemaId, validate(payload): boolean }>>`. Each kind being read or written needs its registered validator. Optional limits may only tighten ceilings. `onDurableStep(step)` is a program-only instrumentation/fault seam; it emits finite step names without payloads or paths. `visiblePayloadPolicy` is a private WeakMap token, not a JSON setting. The only accepted kinds are ledger, critical-journal, result, question, review, revision, snapshot-metadata and explicitly opted-in recorded-visible-response. There is no raw-source, prompt, hidden-reasoning or credential kind.

The store methods are:

```ts
assertCurrent(attempt: WorkflowAttempt): WorkflowAttemptInfo
beginAttempt(binding: WorkflowRunBinding, options?: { signal?: AbortSignal }): Promise<WorkflowAttempt>
appendJournal(attempt: WorkflowAttempt, buildPayload: (context: WorkflowJournalBuildContext) => unknown): Promise<WorkflowVerifiedJournal>
appendJournal(attempt: WorkflowAttempt, payload: unknown): Promise<WorkflowVerifiedJournal>
publish(attempt: WorkflowAttempt, checkpoint: { stage: WorkflowStoreStage; components: readonly WorkflowComponentInput[] }): Promise<WorkflowCommitManifest>
finishAttempt(attempt: WorkflowAttempt): boolean
read(binding: WorkflowRunBinding): WorkflowStoreRead
close(): Promise<void>
```

`WorkflowRunBinding` contains version 1, original logicalRunId/projectId/snapshotId, runSpecHash, configHash, schemaVersion and policyVersion. The two hashes bind the original complete run/budget/time specification and normalized configuration; W checks identity and integrity, while the later adapter must compute and validate the actual hashes against authorized runtime inputs. `WorkflowAttemptInfo` returns the frozen binding and `{ owner, attempt, attemptId }` producing epoch. Attempt is a monotonically increasing ordinal within that logical run, including across owner restarts, and is suitable as its run-scoped fence. The descriptor, its JSON and copied capability objects grant no authority. `assertCurrent` is synchronous, repeatable, uses the private owner/attempt registry and checks the root, current issued owner/attempt epoch and signal. Every queued mutation also pins its flushed attempt marker and checks the newest issued disk epoch after each await. Observed owner/root/attempt fence failure permanently revokes that in-memory capability; removing an injected marker later cannot revive it. `finishAttempt` synchronously ends a physical attempt; an old token cannot release a newer project slot. A committed completed/cancelled/failed manifest is an immediate storage barrier for that same producing epoch: queued/new journal appends, publications and `assertCurrent` reject without modifying files. The generic queue still permits the terminal publication itself to resolve successfully. Orchestration must explicitly call `finishAttempt` to synchronously release the project slot; a new physical attempt can inherit a terminal manifest produced by an earlier epoch without inheriting its physical-attempt barrier.

The synchronous journal builder runs once, inside the same owner queue as position selection and flushed append. Its frozen context is `{ binding, producingEpoch, sequence, previous }`; returning a Promise is rejected. The planned ledger adapter computes `LedgerJournalPosition.hash = H(domain, binding, producingEpoch, sequence, previous W external reference, event)` before its exactly-once ledger `buildState(position)` call, then returns `{ event, state, logicalPosition }`. The physical W record reference hash commits to the full encoded record and is a different value; embedding that same physical hash in its own state would create a self-reference. Builders must not reenter async store mutations or call a provider. No ledger adapter is supplied here. On read it must reconcile every newer verified critical record and the original ledger state before any model admission; manifest/descriptor JSON cannot authorize a new budget or evidence capability.

Owner issuance freezes validated per-run prefixes in an exclusively created, fsynced owner marker; attempt issuance similarly freezes its parent. Current reads use only the newest owner and latest attempt in that owner, plus those exact carried references. They validate all parent manifests and every component referenced by that committed chain, not only the latest payload bodies. Late files in previous epochs are counted for quota but do not advance current. A recognized torn newest marker, journal or manifest makes the run unavailable. An orphan component without a manifest preserves the previous verified prefix. Files are written with exclusive names, bounded before allocation/read, flushed via `fsyncSync`, and never overwritten or garbage-collected. Pending/control/unknown files count in disk admission, and the full serialized transaction is reserved before the first file is opened.

The current implementation is deliberately Windows-only and rejects unsupported platforms. Tests run on the actual local Windows/NTFS host; the unsupported-platform test is skipped on this host. Native W children are bounded and hidden, test real two-process listener contention and close/crash reacquisition, and terminate at each marker/component/journal/manifest open/flush seam. W does not itself suspend a child; suspended-owner/Node-Electron/20x4 contention evidence remains the previously verified primitive probe above. `fsyncSync` plus complete immutable references supports these process-crash observations. Directory-entry ordering, hardware/power-loss durability, other filesystems, network/mapped/cloud roots and adversarial local filesystem races have not been proven. The implementation does not assert M10/M11 completion.
