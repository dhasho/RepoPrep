# P6: complete ledger recovery and durable model dispatch

Date: 2026-11-11. Status: root architecture contract accepted; codec and durable-dispatch seam implemented with focused adversarial evidence. This is not store ownership or M10/M11 acceptance. P6 may proceed alongside P5 after P4. Source inspected at dda316b7c0a2ace6ca209fc0cdf0f9d1f9c6a3cc. The user approved gpt-6.1-sol for this isolated implementation after the requested Luna model was unavailable.

## Source facts and scope

BudgetLedgerSnapshot is diagnostic output, not a restore format: it omits read/tool entries and issued IDs. releaseUnsent and releaseRead remove entries while their IDs stay issued, so persisting only currently visible reservations would permit reused IDs after restart. markUnknownRecovery restores one held request but cannot reconstruct a complete ledger. Both ledger and coordinator start their monotonic clocks anew. ModelGateway's trace callback deliberately swallows errors and cannot be the critical billing journal. At that inspected baseline, CallOptions.beforeRequest returned void and llm.ts called fetch immediately afterward; an asynchronous journal callback cannot be safely inserted under that signature.

Implement a full ledger codec and an awaited durability seam while preserving ordinary non-durable callers and the existing static result/draft formats. Do not claim that these pieces alone implement attempt ownership, storage transactions, snapshot recovery or replay. Those later P6 modules need their own accepted writer/store contracts and integration tests.

## Complete ledger codec v1

Add LedgerStateV1 and explicit exportBudgetLedgerState(ledger, binding) / restoreBudgetLedger(spec, state, options) APIs, or equivalent documented methods with the same boundaries. Keep snapshot() unchanged for existing callers. The recovered state must be deeply immutable and use strict bounded plain-data schemas with no extra keys, accessors or prototype-dependent content.

The binding contains logical runId, projectId, snapshotId, fingerprintRunSpec(spec), schema/policy versions and a trusted durable-journal position. fingerprintRunSpec intentionally excludes run/project/snapshot identity, so all three IDs must also match separately. Configuration hash alone never authorizes a project or recreates a source capability. The loader must validate the committed component hashes and current authorization before invoking restore; standalone user-supplied JSON has no storage authority.

Persist these primary records, not a second independent set of budget totals:

| Record | Required state |
| --- | --- |
| Models | id, stage, estimated input, reserved output, bounded context chars, exact reservation state, complete receipt or null, caller semanticHash, stable semanticOperationHash, immutable requestHash and manifestHash where durable mode is enabled |
| Reads | id, reserved bytes, reserved/settled state, actual bytes or null |
| Tools | id and original stage |
| Issued IDs | every issued ID, including released model/read IDs; no overlap/duplicate/reuse across record classes |
| Safety history | blocked latch and diagnostics whose invalid-operation history is not derivable from live entries; do not clear them on restore |
| Time | logical start UTC, immutable expiry UTC, latest trusted UTC high-water, elapsed monotonic high-water, journal position |

The logical count ceiling remains the existing 100000 issued IDs. Codec bytes are separately capped at 64 MiB; reject oversize before parse/allocation. Implementation must calculate the worst-case encoded size of the bounded entry fields and IDs, and refuse any new durable admission before its state can become unpersistable. Operation keys and lineage commitments use fixed hashes, not unbounded model text. This is a codec limit, not a trace retention change, extra run budget or final store quota. JSON numeric fields are finite safe integers. Bounded diagnostics and current entry values are validated independently; aggregate charged totals, by-stage totals, conservative unknown usage, remaining capacity and overspend are recomputed. Reject contradictory lower diagnostic safety values; a blocked latch may remain true even when current entries alone do not explain its historical cause.

Sort exported records deterministically by ID. Store time and lineage values without source/prompt/private profile/credentials. Preserve the original RunSpec ceilings and generation reserve. A restored over-budget or unknown ledger stays inspectable but cannot admit new work. A malformed or mismatched state fails without yielding a partial usable ledger. Round-trip comparison must cover reservations, reads, tools, released issued IDs, all budget partitions, diagnostics and elapsed capacity, not just token totals.

Recovery interpretation is conservative: settled complete model receipts retain actual usage; dispatched intent without a durably committed complete receipt becomes unknown and retains full reservation. Existing unknown and unknown-unsent stay held. A bare reserved entry is releasable only when the validated critical journal proves no dispatch intent and no protocol violation; the in-memory codec alone cannot prove this. Unsettled read reservations retain full reserved bytes unless the journal proves no project I/O occurred. Never recreate a settled response or question from usage alone.

## Time across restarts

The original logical-run wall-clock deadline remains at most 600000 ms and includes downtime; investigation retains its original shorter deadline as well. Persist logical start/expiry and UTC/monotonic high-water under the same trusted commit. During an attempt, enforce monotonic time and update the trusted UTC high-water. On restore, reject clock rollback or an unprovable anchor; compute consumed time as at least both recorded elapsed and current UTC minus original logical start. Expired runs remain readable but have no new dispatch allowance. No new attempt ID, process restart, codec import or timestamp rounding may replenish time. Terminal elapsed diagnostics stay fixed.

This is an application-clock model, not protection against an administrator forging the system clock and all local state. Fail closed on observed rollback/corruption. Do not make an unsupported tamper-proof clock claim.

## Awaited dispatch durability API

Extend CallOptions.beforeRequest to () => void | Promise<void>, await it before fetch, and repeat abort checks immediately afterward. Synchronous callers keep their current behavior. Explicitly test every supported transport path, including non-stream and stream; never pass a Promise to the old void hook while continuing HTTP. Any additional asynchronous dispatch guard must also be explicitly typed and awaited.

Add a separate ModelGateway durable-admission dependency. Its operations reject on failure and are never routed through best-effort trace. It receives program-owned logical run/attempt/fence, globally unique request ID, semantic-operation key, stage, request/manifest hashes and conservative reservation; it does not receive profile credentials or raw provider errors. A stable operation key commits to the original logical run/project/snapshot/configuration, stage and caller-authorized logical stage/batch/question/version hash. Request/manifest hashes and output cap are separate immutable input commitments associated with that key. Changed rendering, opaque evidence IDs, manifest or cap cannot mint another operation; changing request UUID or physical attempt cannot do so either.

Required order:

1. Check original budget, current attempt/fence, cancellation and exact frozen message/source binding; reserve in the original ledger.
2. Commit and flush the reservation before invoking any transport that can send HTTP.
3. In the pre-fetch hook, synchronously latch the request as starting before the first await. A concurrent or repeated hook cannot start a second durability transaction.
4. Commit and flush dispatch intent. Then recheck authorized snapshot, frozen message hash, current question/version when applicable, attempt/fence, cancellation and remaining deadline. Apply the in-memory dispatched transition only under the same current attempt.
5. Return from the awaited hook; all wrapper asynchronous preparation must finish before the gateway-owned synchronous beforeFetch fence. Wrappers call that repeatable fence before source registration and forward it unchanged. llm.ts invokes it again after onRequest and abort checks, directly before fetch, with no further await. A committed intent whose HTTP execution is uncertain remains conservatively charged, even if no provider work ultimately occurred.
6. On complete provider receipt, validate it and commit/flush it before exposing the operation as recoverably settled. Persist output/result components separately under the later manifest transaction. A usage receipt alone does not establish successful generated output.

Journal failure at reservation/intent prevents HTTP. Failure after intent preserves the durable hold and stops further paid admission. Receipt-write failure must not silently convert the durable state to settled/free: retain the prior durable conservative reservation and an explicit recovery gap. Actual receipt overspend still blocks further work. A broken custom transport that bypasses the guarded hook remains unknown-unsent/unknown, and cannot return accepted unmetered content. Raw errors are mapped to finite static codes.

## Semantic exactly-once boundary

The durable operation registry is keyed only by stable semantic operation identity; the original request identity and immutable input commitments are records associated with that key. At recovery, completed operations reuse only verified recorded output; unknown operations cannot be automatically dispatched again under any UUID. Complete usage with missing output is a charged gap, not permission to regenerate. Reserved-but-proven-unsent operations may be abandoned and replaced only through the official journal transition, preserving issued IDs/history. Explicit paid remeasurement requires a new logical run and concrete authorization; it is distinct from exact resume and never clears the old fees.

All continuations must use a current program-issued attempt capability. The later writer/store module must serialize owner/fence check with journal and manifest publication, and prove cross-process ownership. A plain lock file, PID timeout or atomic single-file rename does not establish that authority. Electron single-instance APIs are a candidate ownership boundary, but namespace/executable scope and store-root identity must be proved by the actual native two-process test before that choice can be frozen. No unsafe stale-lock theft is authorized here.

## Implemented interfaces and integration boundary (2026-11-10)

The implementation lives in workflow/budget-ledger.ts, workflow/ledger-state.ts and workflow/model-journal.ts. The diagnostic snapshot shape is unchanged. New primary-state interfaces are separate:

- LedgerBinding binds runId, projectId, snapshotId, configurationHash, schemaVersion: 1, policyVersion and journal: { sequence, hash }. createLedgerBinding(spec, journal) produces a validated immutable binding. The journal hash is the authority's chain/position marker; it is not a substitute for verification of the complete committed component's content hash.
- LedgerStateV1 contains version, binding, time, blocked, diagnostics, models, reads, tools and issuedIds. Model records add semanticHash, semanticOperationHash, requestHash and manifestHash, each string | null; all four are present together or all null. The codec recomputes the stable operation hash from the original RunSpec, stage and semanticHash and rejects duplicate semantic identities even when their request IDs or input commitments differ. Every collection is sorted and deeply frozen by validation. Time records carry startedUtcMs, expiresUtcMs, utcHighWaterMs, elapsedHighWaterMs and terminalElapsedMs: number | null.
- exportBudgetLedgerState(ledger, binding, projection?) exports canonical primary state. projection: { id, state, usage } prepares a dispatch intent or receipt for the serialized critical writer before mutating live accounting. It is a main-process preparation API, not authority to publish a checkpoint. encodeLedgerState(spec, value), decodeLedgerState(spec, string | Uint8Array) and validateLedgerState(spec, value) enforce the full bounded schema. The maximum encoded envelope is calculated from the bounded metadata, expanded record fields and all issued IDs. The current conservative bound is 1262 metadata bytes plus 853 bytes per model/issued-ID pair when no read/tool records or additional released IDs exist: 78672 pairs fit (67108478 bytes), while 78673 exceed 64 MiB (67109331 bytes). All 100000 pairs would require 85301262 bytes, so the independent byte limit can reject admission before the logical 100000 issued-ID ceiling. Durable admission checks that bound before every new slot. These storage ceilings do not raise the original RunSpec request or token budgets.
- restoreBudgetLedger(spec, value, { authority, clock?, utcClock? }) requires a program-owned LedgerRecoveryAuthority with binding and synchronous assertCurrent(). The loader must verify committed component hashes, current project authorization, journal completeness/position and writer ownership before issuing it. Optional synchronous proveModelUnsent(id) and proveReadUnsent(id) callbacks may return true only from verified critical-journal evidence. Without proof, reserved models become unknown-unsent and reserved reads cannot be released. All read holds retain bytes. Dispatched records become unknown. Unknown and overspent runs remain inspectable and reject paid admission.
- sealBudgetLedger(ledger) fixes terminal elapsed diagnostics and blocks admission; a later coordinator/store terminal transition must call it and persist that state. blockBudgetLedger and retainUnknownModel are conservative main-process transitions used by the dispatch seam. Durable semantic reservations cannot be refunded through releaseUnsent; transactional abandonment with verified no-intent proof remains a later store integration, rather than an in-memory refund.

ModelGatewayOptions.durability accepts a DurableModelJournal. In that mode every ModelCompletionInput must supply durableOperation: { semanticHash, manifestHash }, both fixed SHA-256 hashes. Supplying operation metadata to a gateway without a journal is rejected. The derived semanticOperationHash is SHA-256 over the fixed domain repoprep.workflow.model-operation.v1, original run/project/snapshot/configuration, stage and caller semanticHash only. The caller semanticHash is persisted separately in every context and model record. Frozen message requestHash, manifestHash and reserved outputTokens are immutable commitments stored against that stable identity, not salt for another identity; request UUID and physical attempt are also excluded. The original ledger retains the key after settlement, so complete usage with absent stored output never authorizes a new UUID for the same operation. The program-owned producer and authority validate that the semantic commitment represents the actual current operation; untrusted callers do not get to mint it. A format retry requires the producer to authorize and supply an explicit distinct logical operation kind/version in semanticHash; UUID regeneration, re-rendering or cap recomputation never supplies that authorization. This corrects the unreleased experimental v1 schema; no saved user result/source format or old source data is rewritten, and malformed earlier experimental records fail closed.

DurableModelJournal has binding, attemptId, fence, synchronous assertCurrent(context), and appendAndFlush(event, buildState): Promise<LedgerJournalPosition>. DurableModelContext contains original identities, attemptId/fence, request ID/stage, semanticHash, stable semanticOperationHash, requestHash, manifestHash, input/output reservations and contextChars. DurableModelEvent contains version: 1, kind (reservation/intent/receipt/unknown), context, complete usage or null, outputStatus (uncommitted/missing), and an allowlisted static failureCode. It stores no prompt/source/output text, profile credentials, endpoint or raw error. A local per-ledger queue orders each acknowledged projection and its live transition before the next journal state build, so concurrent gateway instances cannot overwrite a just-flushed receipt with older live state. This queue provides no cross-process ownership. The writer chooses a strictly advancing position and calls buildState(position) exactly once inside its serialized authorized transaction. It resolves only after the complete event and projected ledger are durably flushed. The gateway checks that the acknowledged position exactly matches that build. Cross-process ownership, component hashes, append recovery, missing-record detection, crash-safe manifest publication and output component storage remain the writer/store's responsibility.

The seam flushes reservation before invoking transport, latches the hook synchronously, flushes intent before the final message/source/fence/cancellation/deadline checks, and marks live dispatch only after those checks pass. llm.ts awaits returned Promises from the explicit void | Promise<void> beforeRequest hook (synchronous void hooks preserve their original fetch timing). CallOptions.beforeFetch is optional () => void: it is pure, synchronous and repeatable. The gateway supplies configuration, exact frozen-message/source, attempt/fence, signal and original-deadline checks through it. After all beforeRequest awaits, onRequest and abort checks, llm.ts invokes the final fence, checks abort again and enters fetch without an intervening await. Any non-undefined return, including a Promise, fails the authoritative callback before HTTP; a malformed Promise is drained only to prevent an unhandled rejection, never accepted as authorization. Receipt flush precedes live settlement and returned completion; post-receipt cancellation, fence, source or deadline changes suppress returned output while retaining complete actual usage. Missing/partial durable usage rejects completion and preserves the full unknown reservation. Failed reservation/intent/receipt acknowledgments retain conservative holds, block paid admission and return static WorkflowError codes. Observational trace failures cannot override these transitions. The retrieval evaluation transport wrapper also propagates the returned hook Promise while preserving synchronous hooks, calls the final synchronous fence before its dispatch journal and forwards that same fence to LLM.

Evidence is in ledger-state.test.ts, model-journal.test.ts and llm-durable-hook.test.ts, plus narrow retrieval-eval wrapper regressions. The journal tests create real temporary files with exclusive open, write, FileHandle.sync and close, then read and decode those records for recovery. They use synthetic transport/fetch spies and no real provider or saved credentials. The focused regressions also cover stable semantic identity after complete usage with missing output despite changed cap/messages/manifest/UUID, expanded byte exhaustion before accounting mutation, asynchronous outer preparation with a still-live signal, observer revocation, invalid asynchronous final fences and both protocols in stream/non-stream paths. They prove this module's flush/HTTP ordering and conservative restart interpretation, not native two-process writer authority, M10's full 32 checks or M11's scenario/replay matrix.

## Irreversible durable admission and ordinary-completion activation barrier

The ledger's private internals now expose a program-internal `requiresDurableModelAdmission(ledger)` query. It rejects copied/structural ledger objects and reads the original ledger's irreversible mode; no mutable mode field is added to BudgetLedger or its diagnostic snapshot. Mode is set by the durable creation option, restore, explicit enable, or export. `createModelGateway` captures its journal/admission once and refuses a genuine durable ledger when that admission is missing. Every complete repeats the check before reservation, and `checkDispatch` repeats it after all synchronous authorization/configuration/source/deadline guards, including the last beforeFetch path. Mutating the options object later cannot attach a journal to an old gateway. A durable new reserveModel requires all four valid semantic/request/manifest commitments; the codec continues accepting complete historical nullable rows.

Every ordinary complete acquires a private, per-ledger completion lease before any validation or callback, then releases it in an outer finally only after its full asynchronous processing and failure/unknown/settlement handling have finished. The lease covers buffered-output awaits and observational settlement callbacks as well as transport execution. Each concurrent complete holds a separate lease. A false-to-true activation via enable, export, or another gateway's durable-admission construction refuses while any such lease remains. The refused activation does not switch mode, replenish budgets or alter known/unknown accounting. Codec capacity is checked before a successful activation switches mode. Once all ordinary completions have actually finished, activation may proceed and retains all original history, issued IDs, usage and unknown holds. There is no deferred activation or retroactive journal attachment.

This closes both omitted-journal downgrade and the post-fetch mode-activation gap within the current L module. It does not make activation a recovery authorization. Unknown/unknown-unsent states retain their original conservative costs; historical nullable records remain readable. The future P6 verified cap factory must refuse provider/source admission for unknown, unknown-unsent or unproven historical operation states even if a low-level blocked flag alone is false. It must validate the accepted durable prefix and original operation lineage before granting work. The genuine ledger mode query is not a W capability, a branded recovery authority, or a source permission.

`model-durability-mode.test.ts` supplies 29 focused regressions with a separate synthetic HTTP boundary after beforeFetch, distinct from entering transport. It covers created/enabled/exported/restored healthy ledgers, old gateways/options mutation, forged ledgers, mandatory commitments, guard/await/final-fetch activation attempts, another gateway's activation, HTTP already sent while completion is pending, asynchronous buffered output/settlement traces, caught activation failures, error/cancellation/unknown cleanup, and concurrent completions. Existing nullable-state fixtures deliberately create their historical ordinary rows before export activation. The synthetic journal in these new mode tests is an in-memory ordering seam; real flushed-file journal tests remain separate.
