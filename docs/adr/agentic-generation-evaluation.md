# M08 fixed-evidence generation comparison

Status: offline protocol and implementation preparation; no generation-provider calls are authorized by this document or by the remaining M06 allowance.

## Fixed experiment

Use the twelve frozen development-synthetic generation tasks, four per language. The existing corpus has seven medium and five fine tasks, all with their frozen public objective, role, topic and independent evidence ranges. Run each task with static-control and candidate writers, twice each: 48 cells. No user repository or holdout source is sent in this component experiment.

The runtime projects only `taskId/evidence` from generation labels. Expected-fact and pitfall prose is not supplied to either writer, their prompts or planning cards. All three original asset files are hashed for the data binding. Read the prescribed ranges through the authorized snapshot, charge source reads and issue M03 records; do not widen the frozen input or choose evidence using candidate output.

## Matched writers

Both conditions use the existing generator's quota, normalization, streaming, deduplication and bounded repair/compensation paths. Both get identical public goals, equivalent fixed source ranges/hashes, the same bounded batch plan, citation protocol and prior-question guidance. Both use M07 dispatch manifests, M05 accounting and the same temporary profile. Required evidence bundles remain whole even when repeated across batches.

The candidate additionally receives topic-card planning made only from the task's public topic/objective and provided evidence IDs. The static-control variant withholds that card text. This is a versioned fixed-evidence writer control, not the production static context-selector comparison, a historical baseline, or a full end-to-end quality claim. The production static default remains unchanged. The control also produces source-bound sidecars; no citations are inferred for it.

Within each task, start with control then candidate for one repetition and candidate then control for the other, recording actual order. Review packets hide strategy and writer labels. Source payloads stay separate from default metadata, and model reasoning is not retained.

## Proposed authorization limits

No real call starts without an explicit purpose/source/data/profile-bound authorization and a one-shot claim. The proposed temporary per-request output ceiling is 32,768, identical in both conditions, with a lower 16,384 option. The existing template requests substantial main answers and multiple follow-ups; this headroom does not increase the fixed total allowance. Each request is further capped by its actual remaining output budget. Saved settings are not updated. RunSpec retains the PLAN's per-run limits: 128,000 input, 65,536 output, 600 seconds and at most five model requests for medium or fourteen for fine; repairs, compensation and failed dispatches share the ledger.

The actual task distribution gives a maximum of `4 × (7 × 5 + 5 × 14) = 420` requests over 48 cells. Aggregate input admission is at most 6,144,000 tokens; provider output plus unknown reservations is at most 3,145,728. Known unused reservations may be released only after a complete receipt. Missing usage, profile/source/data mismatch or a budget violation stops further dispatch. Unknown paid work is never automatically repeated. All failed cells, partial prefixes and previous experiments remain accounted for.

## Independent judgment and gate

Two isolated agents review all final main answers and all follow-up answers against the frozen source and rubric without strategy labels or author answer keys. A third adjudicates disagreements. Each record binds packet/input hashes, agent identity and source support. Agent grading is recorded as agent grading; its unavailable provider cost remains unknown and separate from generator receipts.

The material-error denominator includes every reviewed answer, including follow-ups; multiple errors in one answer are one erroneous answer, with categories recorded separately. Topic value uses the frozen four-dimension rubric. Missing review items, unresolved adjudication, incomplete usage or missing source lineage cannot pass.

The M08 gate requires the complete 48-cell matrix, valid existing question/structure contracts, zero unpacked evidence citations, candidate material-error rate no greater than control, topic-value mean at least control minus 0.2, and complete usage. Synthetic execution and report generation alone cannot pass. M13's unseen-repository matrix, release cost/latency thresholds and product switch remain separate later work.
